# 要件定義書

## はじめに

本機能は、ユーザーが生成された議事録に対してフィードバックを提供し、そのデータを収集・分析することで、議事録生成の精度を継続的に向上させるシステムです。ユーザーの評価や修正内容を記録し、将来的なプロンプト改善やモデル最適化に活用します。

## 用語集

- **System**: 議事録作成ツール全体
- **Feedback-System**: ユーザーフィードバック収集・管理システム
- **User**: 議事録作成ツールを使用するエンドユーザー
- **Minutes**: 生成された議事録
- **Rating**: ユーザーによる評価（良い/悪い）
- **Correction**: ユーザーによる具体的な修正指摘
- **Feedback-Record**: フィードバックデータの記録
- **DynamoDB**: フィードバックデータを保存するデータベース
- **API**: フィードバックを送受信するためのインターフェース

## 要件

### 要件 1

**ユーザーストーリー:** ユーザーとして、生成された議事録の品質を評価したい。そうすることで、システムが良い議事録と悪い議事録を学習できるようにする。

#### 受入基準

1. WHEN ユーザーが議事録詳細ページを表示する THEN THE System SHALL 評価ボタン（良い/悪い）を表示する
2. WHEN ユーザーが「良い」ボタンをクリックする THEN THE System SHALL 肯定的評価を記録し、視覚的フィードバックを提供する
3. WHEN ユーザーが「悪い」ボタンをクリックする THEN THE System SHALL 否定的評価を記録し、追加のフィードバック入力フォームを表示する
4. WHEN ユーザーが評価を送信する THEN THE System SHALL 評価データをDynamoDBに永続化する
5. WHEN ユーザーが既に評価済みの議事録を表示する THEN THE System SHALL 既存の評価状態を表示する

### 要件 2

**ユーザーストーリー:** ユーザーとして、議事録の具体的な問題点を指摘したい。そうすることで、システムがどの部分を改善すべきか理解できるようにする。

#### 受入基準

1. WHEN ユーザーが「悪い」評価を選択する THEN THE System SHALL 問題点を記述するテキストエリアを表示する
2. WHEN ユーザーが問題点を入力する THEN THE System SHALL 最大1000文字まで入力を許可する
3. WHEN ユーザーが問題カテゴリを選択する THEN THE System SHALL 事前定義されたカテゴリリスト（要約の精度、重要ポイントの欠落、不要な情報の含有、フォーマットの問題、その他）を提供する
4. WHEN ユーザーがフィードバックを送信する THEN THE System SHALL 問題点とカテゴリをDynamoDBに保存する
5. WHEN ユーザーが議事録の特定セクションを選択する THEN THE System SHALL そのセクションIDをフィードバックに関連付ける

### 要件 3

**ユーザーストーリー:** ユーザーとして、議事録の内容を直接修正したい。そうすることで、システムが正しい出力例を学習できるようにする。

#### 受入基準

1. WHEN ユーザーが議事録の編集モードを有効にする THEN THE System SHALL すべてのセクションを編集可能にする
2. WHEN ユーザーが議事録の内容を変更する THEN THE System SHALL 変更前と変更後の差分を記録する
3. WHEN ユーザーが編集を保存する THEN THE System SHALL 修正履歴をDynamoDBに保存する
4. WHEN ユーザーが編集を保存する THEN THE System SHALL 元の議事録と修正後の議事録の両方を保持する
5. WHEN 修正が保存される THEN THE System SHALL 修正日時とユーザーIDを記録する

### 要件 4

**ユーザーストーリー:** システム管理者として、収集されたフィードバックデータを分析したい。そうすることで、議事録生成の改善点を特定できるようにする。

#### 受入基準

1. WHEN 管理者がフィードバックデータを要求する THEN THE System SHALL すべてのフィードバック記録を取得するAPIを提供する
2. WHEN フィードバックデータが取得される THEN THE System SHALL 評価、問題カテゴリ、修正履歴を含む完全なデータを返す
3. WHEN 管理者が期間を指定する THEN THE System SHALL 指定期間内のフィードバックのみを返す
4. WHEN 管理者が統計情報を要求する THEN THE System SHALL 肯定的評価率、問題カテゴリ別の分布、修正頻度を計算して返す
5. WHEN フィードバックデータが取得される THEN THE System SHALL 個人を特定できる情報を適切に処理する

### 要件 5

**ユーザーストーリー:** システムとして、フィードバックデータを効率的に保存・取得したい。そうすることで、大量のフィードバックを扱えるようにする。

#### 受入基準

1. WHEN フィードバックが送信される THEN THE System SHALL 一意のフィードバックIDを生成する
2. WHEN フィードバックがDynamoDBに保存される THEN THE System SHALL jobIdをパーティションキーとして使用する
3. WHEN フィードバックがDynamoDBに保存される THEN THE System SHALL タイムスタンプをソートキーとして使用する
4. WHEN 議事録に対するフィードバックが取得される THEN THE System SHALL jobIdでクエリを実行する
5. WHEN データが保存される THEN THE System SHALL すべてのフィールドが適切なデータ型で保存されることを検証する

### 要件 6

**ユーザーストーリー:** ユーザーとして、フィードバック送信時にエラーが発生した場合に通知を受けたい。そうすることで、フィードバックが正しく記録されたか確認できるようにする。

#### 受入基準

1. WHEN フィードバック送信が成功する THEN THE System SHALL 成功メッセージを表示する
2. WHEN フィードバック送信が失敗する THEN THE System SHALL エラーメッセージを表示する
3. WHEN ネットワークエラーが発生する THEN THE System SHALL 再試行を促すメッセージを表示する
4. WHEN バリデーションエラーが発生する THEN THE System SHALL 具体的なエラー内容を表示する
5. WHEN フィードバック送信中 THEN THE System SHALL ローディング状態を表示する

### 要件 7

**ユーザーストーリー:** システムとして、フィードバックデータを将来の改善に活用したい。そうすることで、議事録生成の精度を継続的に向上できるようにする。

#### 受入基準

1. WHEN フィードバックデータがエクスポートされる THEN THE System SHALL JSON形式でデータを出力する
2. WHEN 修正履歴がエクスポートされる THEN THE System SHALL 元のテキストと修正後のテキストをペアで出力する
3. WHEN 問題カテゴリが分析される THEN THE System SHALL 各カテゴリの出現頻度を計算する
4. WHEN 評価データが分析される THEN THE System SHALL 時系列での評価推移を提供する
5. WHEN データがエクスポートされる THEN THE System SHALL プライバシーに配慮した形式で出力する

### 要件 8

**ユーザーストーリー:** システムとして、収集したフィードバックを使ってプロンプトを自動的に改善したい。そうすることで、議事録生成の品質が継続的に向上するようにする。

#### 受入基準

1. WHEN 否定的評価が一定数蓄積される THEN THE System SHALL 問題パターンを自動分析する
2. WHEN 修正履歴が分析される THEN THE System SHALL よく修正される箇所の共通パターンを抽出する
3. WHEN 問題パターンが特定される THEN THE System SHALL プロンプト改善の提案を生成する
4. WHEN プロンプト改善提案が生成される THEN THE System SHALL 管理者に通知を送信する
5. WHEN 改善されたプロンプトが適用される THEN THE System SHALL 新旧プロンプトのバージョン管理を行う

### 要件 9

**ユーザーストーリー:** システムとして、フィードバックに基づいて議事録生成の品質を測定したい。そうすることで、改善の効果を定量的に評価できるようにする。

#### 受入基準

1. WHEN 議事録が生成される THEN THE System SHALL 品質スコアを計算する
2. WHEN 品質スコアが計算される THEN THE System SHALL 過去のフィードバックデータを参照する
3. WHEN 肯定的評価が多い議事録の特徴が分析される THEN THE System SHALL その特徴を品質指標として記録する
4. WHEN 品質指標が更新される THEN THE System SHALL 新しい議事録生成時にその指標を適用する
5. WHEN 品質スコアが閾値を下回る THEN THE System SHALL 警告を発行する

### 要件 10

**ユーザーストーリー:** システムとして、ユーザーの修正内容から学習データセットを構築したい。そうすることで、将来的なモデルのファインチューニングに活用できるようにする。

#### 受入基準

1. WHEN ユーザーが議事録を修正する THEN THE System SHALL 修正前後のペアを学習データとして記録する
2. WHEN 学習データが一定数蓄積される THEN THE System SHALL ファインチューニング用のデータセット形式に変換する
3. WHEN データセットが生成される THEN THE System SHALL 入力（元の議事録）と期待出力（修正後の議事録）のペアを含む
4. WHEN データセットが生成される THEN THE System SHALL データ品質チェックを実行する
5. WHEN データセットがエクスポートされる THEN THE System SHALL Bedrock等のファインチューニングサービスに対応した形式で出力する
